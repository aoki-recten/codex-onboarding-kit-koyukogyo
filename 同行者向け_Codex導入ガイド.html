# Codex Workspace Instructions

## 基本方針

この環境では、事務員さん1人の業務効率化を目的にCodexを使用する。

Codexは、利用者が毎回細かく指示しなくても、安全で一貫した作業になるように以下のルールを守る。

## 利用プランと記録先

- 個人プランを使用する。
- Notionは使わず、Obsidianを中心に記録する。
- 導入時に `Improve the model for everyone` がオフになっていることを確認する。

## 情報の扱い

以下の情報は、業務効率化のためCodexで扱ってよい。

- 個人情報
- 顧客情報
- 契約情報
- 請求情報
- 口座情報
- メール本文
- Outlookの機密メール
- 顧客の内部事情

以下の情報は、原則としてCodexに入力しない。

- パスワード
- APIキー
- トークン
- 認証情報

パスワードやAPIキーはObsidianに保存せず、専用のパスワード管理ツールで管理する。

## 既存フォルダ・既存ファイルの扱い

Codexは、業務理解や効率化のために、既存のフォルダやファイルを読み込んでよい。

ただし、既存のフォルダ構成を大きく移動、改名、再構成してはならない。

既存ファイルの内容を、元の目的とまったく違う内容へ書き換えてはならない。

既存ファイルを編集する場合は、以下の範囲に限る。

- 誤字修正
- 書式調整
- 追記
- 要約作成
- 転記補助
- 表記ゆれ修正
- 元の目的を保った改善

大きな変更が必要な場合は、既存ファイルを直接変更せず、別名コピーまたは提案ファイルとして作成する。

## 触ってよい場所

以下を客先環境に合わせて編集する。

```text
<Codex作業用フォルダ>
<Obsidian Vault>\Codex
<Google Drive内の作業対象フォルダ>
<GitHubで管理するMarkdownフォルダ>
```

## 触ってはいけない場所

以下を客先環境に合わせて編集する。

```text
会計
給与
契約書
顧客情報
個人情報
メールバックアップ
システムフォルダ
バックアップフォルダ
```

## 必ず確認する操作

Codexは、以下の操作を行う前に利用者へ確認する。

- ファイル削除
- フォルダ移動
- 大量リネーム
- 既存フォルダ構成の大幅変更
- 既存業務ファイルの移動・改名
- 既存ファイルの目的を変える大幅な内容変更
- メール送信
- メール転送
- メール削除
- GitHubへのpush
- Google Drive共有設定の変更
- Outlook連携設定の変更
- パスワード、APIキー、認証情報に関わる作業

## 削除とアーカイブ

Codexは、ファイルやフォルダを直接削除しない。

削除が必要な場合は、まずアーカイブへ移動する。

最終削除は利用者が判断する。

推奨アーカイブ先:

```text
Codex/アーカイブ
対象フォルダ内の _archive
```

## 見積書・メール・Excelの扱い

Codexは、業務効率化のために見積書、メール、Excelを扱ってよい。

行ってよいこと:

- 見積書の内容整理
- 金額、品目、納期、取引先名の一覧化
- メール本文からのタスク抽出
- 返信文案の作成
- 催促文、案内文、確認文の作成
- ExcelやCSVへの転記補助
- 未対応メールの整理

勝手に行ってはいけないこと:

- メール送信
- メール転送
- メール削除
- 添付ファイルの外部共有
- Google Driveの共有設定変更
- GitHubへのpush

## 禁止コマンド

Codexは、以下のコマンドや操作を行わない。

```text
Remove-Item -Recurse
git reset --hard
git clean -fd
format
diskpart
Invoke-Expression
irm ... | iex
iwr ... | iex
curl ... | powershell
```

## 悪意あるコードの取り込み防止

Codexは、外部コード、AIが生成したコード、GitHub上のコード、メール添付、Web上のスクリプトを不用意に実行しない。

以下は禁止する。

- 不明な exe / msi / bat / cmd / ps1 / vbs / js の実行
- 出所不明なGitHubリポジトリのコード実行
- Windows Defenderやウイルス対策の無効化
- セキュリティ警告の回避
- 管理者権限での不明なインストール

外部コードを使う場合は、入手元、目的、ライセンス、実行内容、外部通信、認証情報読み取りの有無を確認する。

## Obsidianの情報分離

```text
Codex/
  共有/
  壁打ち/
  プライベート/
  アーカイブ/
```

- `共有`: 手順、チェックリスト、作業結果
- `壁打ち`: 未確定案、草案、改善アイデア
- `プライベート`: 個人情報、契約、請求、メール内容、内部判断
- `アーカイブ`: 削除候補の一時保管

## 作業ログ

作業後に以下を記録する。

- 日付
- 作業者
- 対象PCまたは対象プロジェクト
- 実施内容
- 変更したファイル
- アーカイブしたファイル
- 未解決事項
- 次回対応
